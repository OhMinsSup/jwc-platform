# ADR-0025: 응답 시트를 시트 "표"로 만들기와 폼별 시트 위치

- 상태: 채택
- 작성일: 2026-11-11
- 관련: ADR-0006(응답 저장소 어댑터), ADR-0002(행 찾기)
- 변경: 운영 컬럼 헤더(`응답 ID`·`제출일시`·`수정일시` → `ID`·`신청일시`), 스프레드시트 ID의 출처(환경 변수 하나 → 폼별 설정 + 기본값)

## Problem 1-Pager

- 배경: 운영자는 실제 행사에서 손으로 다듬은 신청자 시트(짙은 초록 헤더, 흰색/연회색 줄무늬, 필터, 열 너비, 드롭다운, "2026년 06월 26일"·"오후 10:00" 서식)를 써 왔다. 앱이 만든 탭은 서식이 없고 날짜·시간을 `2026-06-26 14:30` 글자로 썼다.
- 문제: (1) 앱이 만든 탭을 매번 손으로 꾸며야 하고, 시간 글자는 시트에서 시간 순으로 정렬되지 않는다. (2) 스프레드시트가 환경 변수 하나로 고정돼 행사별 스프레드시트를 쓸 수 없다.
- 목표: 응답 탭이 Google 시트의 "표"(데이터 테이블)로 만들어져 머리글·줄무늬·필터·열 타입·드롭다운을 시트가 직접 관리하고, 날짜·시간은 시트의 날짜 값으로 저장된다. 관리자가 폼마다 스프레드시트와 탭을 바꿀 수 있다.
- 비목표: 기존 응답을 새 위치로 옮기기, 운영자가 고친 표 설정(열 타입 등) 되돌리기, 표 꼬리글(footer)·스마트 칩 열.
- 제약: 이미 운영 중인 탭(이전 헤더, 글자 날짜)을 계속 읽고 써야 한다. 서비스는 `SubmissionStore` 포트에만 의존한다.

## 결정

- 열 구성: `ID`, `신청일시`, 질문(표시 순서), `납입여부`(결제가 있는 폼만). `수정일시`는 새 탭에 만들지 않는다.
  - 이전 헤더(`응답 ID`, `제출일시`)는 같은 컬럼으로 인식한다(`LEGACY_SYSTEM_HEADERS`). 이전 탭의 `수정일시` 열은 더 이상 갱신하지 않고 보존한다.
  - 현재·이전 운영 헤더는 새로 편집·발행하는 정의에서 질문 헤더로 쓸 수 없다(무결성 검사). 이미 발행된 정의는 `parseStoredFormDefinition`으로 읽어 이 결정 이전부터 예약된 이름(`응답 ID`·`제출일시`·`수정일시`·`납입여부`)만 막는다. 그래서 `ID`/`신청일시` 질문을 가진 옛 폼도 계속 열리고, 시트에서는 운영 컬럼이 이겨 그 질문은 시트 열을 갖지 않는다.
- 값: 날짜/시간/일시 답변은 스프레드시트 일련번호(1899-12-30부터의 일수)로 쓰고, 열에 `yyyy년 mm월 dd일`·`am/pm h:mm` 서식을 건다. 읽기는 `UNFORMATTED_VALUE`+`SERIAL_NUMBER`로 원래 값을 읽어, 운영자가 표시 서식을 바꿔도 해석이 같다. 이전 글자 날짜도 계속 읽는다. `신청일시`는 참고 시트처럼 글자(`2026년 06월 01일 (월) 20:45`)로 쓴다.
- 표: 응답 탭은 `addTable`로 만든 시트 "표"다. 머리글 #356854·줄무늬 #FFFFFF/#F6F8F9는 표 행 속성, 필터는 표 기본 기능, 열 타입은 값 종류(text→TEXT, number→DOUBLE, date→DATE, time→TIME, datetime→DATE_TIME)이고 선택지가 있는 열(선택형·예/아니오·납입여부)은 DROPDOWN이다. 표 이름은 탭 이름에서 글자·숫자·밑줄만 남겨 스프레드시트 안에서 겹치지 않게 정한다.
  - 새 응답 행은 `AppendCellsRequest`(`sheetId` + `tableId`)로 표 본문의 첫 빈 행에 넣는다. `sheetId`를 빼면 API 문서("tableId가 우선한다")와 달리 실제로는 기본값 0(첫 탭)에 붙는다. 2026-11-11 실제 스프레드시트로 확인했으며, 둘을 함께 보내면 표 안에 들어가고 표 범위가 늘어난다. `values.append`는 표 범위를 넓히지 않을 수 있기 때문이다. 기존 행 갱신은 그대로 `values.update`다.
  - 다시 준비할 때: A1에서 시작하는 표가 있으면 그 표를 쓰고, 새 열이 생길 때만 `updateTable`로 범위와 열 속성을 넓힌다(API가 열 속성 배열을 통째로 바꾸므로 기존 열 속성은 읽은 그대로 돌려보낸다). 표가 없는 기존 탭은 기존 응답 행까지 덮는 표를 만들고, 겹치는 이전 버전의 A1 줄무늬와 기본 필터를 먼저 지운다. A1이 아닌 곳에 다른 표가 있는 탭은 겹칠 수 있어 표·열 서식을 건드리지 않는다(1행 고정만).
  - 열 너비·글자 서식은 새 열에만, 날짜·시간 서식(`yyyy년 mm월 dd일`, `am/pm h:mm`)은 값이 일련번호라 기존 열에도 다시 건다.
- 위치: `forms.spreadsheet_id`(null = 기본 `GOOGLE_SPREADSHEET_ID`)와 `forms.sheet_name`. 관리자 폼 화면의 "설정" 탭에서 URL 또는 ID와 탭 이름을 바꾼다. 발행된 폼은 저장 전에 새 위치를 준비해 권한 문제를 먼저 알린다. 같은 스프레드시트의 같은 탭은 두 폼이 쓸 수 없다(유니크 인덱스 + null을 기본 ID로 채워 비교하는 서비스 검사).
- 조립: `runtime.submissionStore(spreadsheetId)`가 스프레드시트별 어댑터를 캐시하고 토큰 공급자는 공유한다. 포트(`StoreTarget`)는 바꾸지 않는다.

## 구조 (데이터 중심)

정의(표) → 계획(순수 값) → 실행(값을 요청으로 바꾸기만)으로 나눈다. 열 하나·타입 하나·운영 규칙 하나를 바꿀 때 고칠 곳이 한 곳이다.

| 층   | 위치                                                                                                                                                                         | 내용                                                                                                                                                                                       |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 정의 | `form-core` `SYSTEM_COLUMN_TABLE`, `sheet/system-cells.ts`                                                                                                                   | 운영 컬럼 행(헤더, 이전 이름, 배치, 결제 조건)과 키별 셀 변환                                                                                                                              |
| 정의 | `form-core` 필드 타입 레지스트리 `sheet: { value, choices? }`, `sheet/cells.ts` `CELL_CODECS`                                                                                | 질문 타입별 값 종류와 선택지, 값 종류별 셀 변환                                                                                                                                            |
| 정의 | `submission-store` `sheet-style.ts`                                                                                                                                          | Google 표시 정보: 표 색, 값 종류별 표 열 타입·서식(`reapply`), 열 너비                                                                                                                     |
| 계획 | `submission-store` `layout-plan.ts` `planSheetLayout`                                                                                                                        | 탭 상태 + 정의 → `SheetLayoutPlan` (덮어쓰기 규칙이 모두 여기)                                                                                                                             |

| 위치 | `@jwc/google/spreadsheet-ref`(ID·주소·탭 이름 규칙), `@jwc/submission-store/bound`(공간에 묶인 저장소), 앱 `forms/domain/sheet-location.ts`·`forms/server/response-store.ts` | Google 형식은 패키지가 알고, 앱은 정책만 둔다: 빈 값 = 기본 스프레드시트, 사용자 문장, 같은 위치 판정. 저장된 설정을 경계에서 한 번 `ResponseSheet`로 해석해 묶인 저장소만 서비스에 넘긴다 |

## 리뷰 후 보완 (2026-11-11)

- 탭 위치 유니크: `forms.spreadsheet_key = coalesce(spreadsheet_id, '')`, `sheet_name_key = lower(sheet_name)` 가상 생성 열에 유니크 인덱스를 둔다. 기본 스프레드시트(null)끼리, 탭 이름 대소문자 차이까지 DB가 막는다(검사와 저장 사이 경쟁 포함). drizzle가 SQLite 식 인덱스를 잘못 따옴표 처리해 생성 열을 쓴다. 기본 ID를 직접 적은 설정은 저장 시 null로 정리한다.
- 탭 이름 비교는 대소문자를 무시한다(Google 규칙, `@jwc/google/spreadsheet-ref`의 `sameSheetTitle`). SQLite `lower`는 ASCII만 바꾸므로 한글·ASCII 외 대소문자 쌍은 앱 검사가 맡는다.
- 쓰기 경로의 탭 정보 캐시(`tab-cache.ts`, 저장소 인스턴스 수명): 탭마다 처음 쓸 때 한 번 sheetId·표 ID를 읽고 날짜·시간 서식을 다시 건다. 발행 전에 만들어진 탭에서도 일련번호가 숫자로 보이지 않고, 새 응답마다 메타데이터를 읽지 않는다. 표 쓰기가 400이면 캐시를 버리고 한 번만 다시 시도한다(400은 반영되지 않은 요청이라 중복 없음).
- 새 폼의 탭 이름이 겹치면 거절하지 않고 `slug-2`, `slug-3`…을 쓴다(만들기 화면에 탭 칸이 없다).

## 일시 질문을 날짜 열·시간 열로 나누기 (2026-11-11)

- 일시(datetime) 질문은 시트에서 날짜 열 + 시간 열로 나눈다(레지스트리 `sheet.parts: ["date", "time"]`). 표 열 타입은 DATE·TIME이라 운영자가 표에서 날짜 선택기·시간 값으로 고칠 수 있다. 신청 화면과 저장 값(`YYYY-MM-DDTHH:mm`)은 그대로다.
- 열 이름: "…일시"면 "…일자"/"…시간"(예: 참석일시 → 참석일자·참석시간), 아니면 "… 날짜"/"… 시간". 편집기 "시트 열 이름" 안내에 실제 열 이름을 보여 준다. 나눈 열 이름도 시트 헤더 중복 검사에 들어간다(새 정의만, 저장된 정의는 이전 규칙).
- 읽기: 두 열을 합쳐 일시 질문 검증을 그대로 거친다. 한쪽만 있으면 "날짜와 시간을 모두 입력해주세요". 이전 버전의 통짜 "참석일시" 열은 새 탭에 만들지 않지만, 있으면 함께 갱신하고 나눈 열이 비었을 때만 읽는다.
- 대안: 폼 정의에서 질문 자체를 날짜·시간 둘로 나누기는 신청 화면이 바뀌고 일시 범위(min/max·간격) 검증을 잃어 미채택.
- 확인된 제약(2026-11-11 실제 스프레드시트): 표의 DATE·TIME 열은 표가 정한 표시 형식(`M/d/yyyy`, `h:mm:ss am/pm`)을 강제한다. 셀 서식(`yyyy년 mm월 dd일`)을 나중에 걸거나 행 추가와 함께 보내도 덮인다(지역 설정 ko_KR에서도). 값과 편집은 정상이다. 한국어 표시가 꼭 필요하면 표 열 타입을 TEXT로 두고 서식을 거는 방법이 있지만 날짜 선택기 편집을 잃는다.

## 경계: 무엇이 패키지에 있고 무엇이 앱에 있나

- 패키지(`@jwc/google`, `@jwc/submission-store`): Google이 정한 사실(스프레드시트 ID·주소 형식, 탭 이름 제한, 표·셀·서식 API)과 저장소 종류와 무관한 사용법(`bindSubmissionStore`).
- 앱: 이 서비스의 정책과 조립(기본 스프레드시트 = 환경 변수, 한 탭은 한 폼만, 사용자 문장과 설정 화면, 서비스 계정으로 어댑터 조립, DB의 `spreadsheet_id`·`sheet_name`).
- 위치를 저장소와 무관한 JSON으로 일반화하는 방안(포트가 입력 해석·주소를 제공)은 어댑터가 Google 하나뿐이라 미뤘다. 두 번째 실제 저장소가 생길 때 다시 본다.
- 앱 domain의 I/O 금지 린트(`vite.config.ts` `IO_MODULES`)에서 `@jwc/google/spreadsheet-ref`만 예외로 둔다 (순수 함수).

## 영향

- 배포 전에 마이그레이션(`forms.spreadsheet_id` 추가, `sheet_name` 단독 유니크 → `(spreadsheet_id, sheet_name)` 유니크)을 적용한다.
- 기존 탭: 다음 발행 때 기존 응답까지 덮는 표로 바뀌고(이전 버전의 A1 줄무늬·기본 필터는 지워짐) 날짜 서식이 걸린다. 기존 열 순서·너비·값은 그대로다. 이후 새로 쓰는 날짜 칸은 날짜 값이 된다.
- 위치를 바꿔도 기존 응답은 옮겨지지 않는다(화면에서 안내).
