# ADR-0017: 글꼴 교체 중 관리자 페이지 머리의 줄 배치 유지

- 상태: 채택
- 작성일: 2026-11-09
- 관련: ADR-0008, ADR-0016

## Problem 1-Pager

- 배경: macOS의 전 페이지 모바일 측정은 통과했지만 Linux CI의 관리자 폼 목록 CLS는 5회 모두 0.1687225810으로 0.1 예산을 초과했다.
- 문제: 페이지 머리의 줄바꿈을 설명의 고유 너비에 맡겨 대체 글꼴과 웹 글꼴의 글자 폭 차이가 동작 버튼의 줄을 바꾼다. CI의 글꼴 환경을 포함한 회귀 검사가 없었다.
- 목표: 제목·동작 영역의 공간 계산을 안정화하고 플랫폼에 독립적인 브라우저 회귀 검사로 글꼴 교체를 검증한다.
- 비목표: 성능 예산 완화, 초기 CLS 누락, 글꼴·색상·버튼 디자인 교체, 실제 비밀값 접근.
- 제약: 공개 더미 설정과 격리된 D1을 사용한다. 기존 웹 글꼴과 `font-display: swap`, 긴 제목과 여러 동작의 반응형 줄바꿈을 유지한다.

## 재현과 원인

- 공개 Debian 패키지의 WenQuanYi Zen Hei를 임시 테스트에만 적용하고 CDN 글꼴 응답을 보류해 전후 위치를 비교했다. 제품·시스템 글꼴은 변경하지 않았다.
- Pixel 7의 412px 너비에서 대체 글꼴의 설명 너비는 약 295px, SUIT는 약 254px였다. `flex-wrap`의 줄 배치가 고유 너비에 의존해 동작 버튼이 `(16, 148.5)`에서 `(325, 80)`으로 이동하고 목록 전체가 위로 44px 움직였다.
- 브라우저의 실제 layout-shift 항목에서 CLS 0.1683533979를 재현했다. 검색 입력 전 발생했으며 집계 오류나 검색 결과 변경이 원인이 아니었다.
- 임시 Linux 글꼴과 DOM 진단은 저장소·CI 보고서에 포함하지 않는다.

## 대안

- A: 글꼴이 로드된 뒤 측정을 시작하거나 CLS를 초기화한다. 변경량은 작지만 실제 초기 레이아웃 이동을 숨기므로 채택하지 않는다.
- B: `font-display: optional`로 늦은 교체를 막는다. 이동은 줄일 수 있지만 사용자에게 기존 글꼴이 적용되지 않을 수 있어 채택하지 않는다.
- C: 제목 영역에 12rem의 flex basis와 남은 공간 분배를 지정한다(채택). 설명의 고유 너비 대신 제목 열의 기준 공간으로 줄을 배치한다. 설명은 열 안에서 줄바꿈하고, 여러 동작이 들어갈 공간이 없으면 다음 줄을 사용한다.

## 영향과 회귀 검사

- 변경은 공통 `PageHeader`의 제목 영역 클래스 두 개로 한정한다. 폼 목록·관리자 관리·폼 상세의 머리에 적용되며 저장·인증·라우트·검색 비노출에는 영향이 없다.
- 앱의 기존 글꼴을 `@font-face`의 `size-adjust: 116%`로 재사용해 실제로 확인한 폭 차이를 모사한다. OS 글꼴 설치나 별도 바이너리 fixture가 필요 없다. 375px·412px·1280px에서 대체 폭과 최종 폭 모두 동작 버튼이 제목과 같은 줄에 있는지 검사한다.
- 이 검사는 글꼴 폭에 따른 요소 위치의 회귀 검사다. 실제 cold-load Core Web Vitals는 기존 17개 화면 × 5회 검사에서 계속 측정하며 예산과 수집 시점은 바꾸지 않는다.

## 검증

- 수정 전 회귀 검사는 375px·412px에서 실패했다. 412px의 버튼 y 위치는 제목의 80px 대신 148.5px이었다. 1280px는 통과했다.
- 수정 후 세 너비의 회귀 검사가 모두 통과했다. 동일한 Linux 대체 글꼴·웹 글꼴 응답 보류 조건의 CLS는 0.1683533979에서 0.0101760785로 내려갔다. 이는 통제된 재현 실험이며 CI·운영 전체의 개선율을 뜻하지 않는다.
- 수정 파일 포맷·린트, 의존성·미사용 검사, 전체 타입 검사와 단위 테스트 319개가 통과했다.
- `PERFORMANCE_SAMPLES=1`로 17개 화면의 성능 예산을 각 1회 재확인하고 세 너비의 회귀 검사도 함께 통과했다. CI 기본값인 화면별 5회와 지표 예산은 유지한다.
