# ADR-0012: 로컬 개발 환경과 비밀값 주입

## Problem 1-Pager

- 배경: 로컬 개발은 평문 `apps/web/.env`, 운영은 Cloudflare Worker Secrets를 사용한다.
- 문제: Git에서 제외한 파일도 AI가 읽을 수 있고, 개발 프로세스에 운영 권한이 전달될 수 있다.
- 목표: `pnpm dev`는 실제 비밀값 없이 실행하고, 실제 연동은 dotenvx 암호화와 macOS 키체인으로 관리한다.
- 비목표: 운영 저장소 변경, 운영 키 교체, 기존 비밀값의 로그 출력, 이 저장소에서 AI 샌드박스 자체 구현.
- 제약: Void의 환경 스키마와 런타임 경계를 유지하고, 복호화 키는 커밋하지 않는다.

## 대안

- A. 평문 `.env` 유지: 설정은 간단하지만 AI의 파일 읽기를 막지 못한다.
- B. 개발 기본값과 암호화된 실제 연동 설정 분리(채택): 기존 `with-env` 패턴을 유지하고 기본 실행에 키가 필요 없다. 복호화 권한의 별도 관리가 필요하다.
- C. 개발도 Cloudflare에서만 실행: 로컬에 실제 키를 두지 않지만 연동 검증마다 원격 실행이 필요하다.

## 결정과 영향

- 기본 명령 이름은 `dev`다. 실제 외부 서비스 연동은 `dev:real`로 구분한다.
- dotenvx가 프로세스 시작 전에 값을 주입한다. 암호화 파일은 Void가 자동으로 읽는 앱 루트 `.env`와 분리한다.
- 개발용 복호화 키는 macOS 키체인에 보관하고, 복구 사본은 별도의 안전한 저장소에 둔다.
- 운영은 개별 값을 Cloudflare Secrets에 등록한다. Worker 내부에 dotenvx 복호화 로직을 추가하지 않는다.
- 가정: 기본 개발은 메모리 응답 저장소와 SMS 로그 모드로 충분하다. 실제 Google·문자 인증 검증은 별도 개발 계정으로 수행한다.
- 키체인은 저장 시 보호다. AI의 복호화·프로세스 조회·배포 권한을 차단하려면 별도 사용자나 컨테이너 경계가 필요하다.
- `.env.keys`와 평문 환경 파일은 Git에서 제외한다. AI는 실제 비밀 파일·복호화 키·배포 자격 증명을 조회하지 않는다.

## 검증

- `pnpm verify`: 정적 검사·의존성·타입 검증과 단위 테스트 299개 통과. 신규 회귀 테스트는 실제 CLI의 더미 설정 덮어쓰기, 암호화 왕복, 키 누락 시 실행 중단을 확인한다.
- `pnpm -C apps/web build`: 통과.
- `pnpm -C apps/web test:e2e`: 공개 신청 성공·실패와 관리자 인증 시나리오 4개 통과. CI도 같은 더미 주입 명령을 사용한다.
- 실제 루트 `pnpm dev`의 HTML과 미인증 세션 API가 HTTP 200으로 응답한다.
- 기존 평문 파일 4개를 암호화하고, 키체인으로 복호화한 값과 원본을 비교한 뒤 평문 원본을 제거했다. 보관본과 실제 연동 파일은 Git에서 제외한다.
- 실제 연동 설정의 환경 스키마 검증도 통과했다. 실제 값은 어느 검증 출력에도 포함하지 않았다.
- 기존 Turbo 타입 검사 캐시의 미생성 output 경고와 CSS sourcemap 경고는 이 변경의 범위에서 수정하지 않았다.
- AI 작업 환경 자체의 격리와 별도 복구 백업은 이 저장소 설정으로 생성되지 않는다.
