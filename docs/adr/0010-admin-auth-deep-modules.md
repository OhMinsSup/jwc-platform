# ADR-0010: 관리자 인증 모듈의 인터페이스 단순화

- 상태: 채택
- 작성일: 2026-11-05
- 관련 결정: ADR-0009, docs/plans/admin-auth-data-oriented-review.md

## Problem 1-Pager

- 배경: SMS·TOTP 인증은 구현되어 있으나 가입 테스트가 실제 가입 조정 함수를 우회하고, 라우트가 세션과 인증 상태를 따로 조회한다.
- 문제: 호출자가 허용 목록·지정 번호·SMS 소비·가입 승인 순서를 알아야 하며 정책값과 이동 판단도 분산되어 있다.
- 목표: 가입 순서를 깊은 모듈 내부로 모으고 같은 인터페이스에서 테스트한다. 정책·등록 정보·접근 결정을 공유해 호출자 판단을 줄인다.
- 비목표: 인증 엔진 교체, DB 마이그레이션, 범용 규칙 엔진, 실제 SMS 발송·운영 배포, 프로세스 종료 복구 보장의 추가.
- 제약: 기존 이메일·비밀번호·SMS·TOTP와 초대/최초 가입 조건, DB 유니크 제약, 의존 방향, 비밀값 비노출을 유지한다.

## 대안

- A: 가입 모듈이 판단·초대 선점·OTP 소비·승인 범위·계정 생성·실패 복구를 처리하고, 실제 인증 엔진과 초대 adapter를 주입한다(채택). 장점은 호출자와 테스트가 같은 동작을 사용하고 변경이 모듈 안에 모이는 것이다. 단점은 내부 테스트 seam을 위한 의존성 계약이 필요하다. 위험은 기존 실행 순서 변경이며 성공·실패 테스트로 고정한다.
- B: 모든 인증 작업을 단일 명령·범용 정책 해석기로 실행한다. 장점은 다양한 흐름을 확장하기 쉽다는 것이다. 단점은 명령과 실행기 사이 추적 비용이며, 위험은 라이브러리의 세션 보장을 새 해석기에 잘못 옮기는 것이다.

## 의존성과 seam

- 경로·접근 판단·정책은 in-process다. 순수 함수와 데이터로 테스트한다.
- Better Auth와 D1은 local-substitutable이다. 같은 Better Auth 처리기와 메모리 adapter, 초대 저장소의 로컬 adapter로 가입 모듈을 검증한다.
- Solapi는 true external이다. 기존 SMS 인터페이스를 유지하고 테스트에서는 가짜 발송기를 쓴다.
- 가입 모듈의 외부 인터페이스는 가입 요청 하나다. DB·인증 엔진 주입은 내부 seam이며 HTTP나 UI 계약에 노출하지 않는다.

## 결정과 영향도

- 인증 정책·입력 스키마를 domain에 두고 인증 옵션·검증·UI가 같은 공개 정책값을 사용한다.
- 허용 이메일과 번호 목록을 정규화한 관리자 등록 정보로 조합한다. 등록되지 않은 이메일과 번호가 없는 등록 정보를 구분하고, 두 경우 모두 관리자 권한을 부여하지 않는다.
- 순수 접근 판단은 ready일 때만 최소 관리자 식별 정보를 담는다. 라우트와 관리자 작업은 같은 결정 모델을 사용한다.
- TOTP 등록과 로그인 완료는 구분한다. 로그인 세션 발급은 계속 Better Auth가 책임진다.
- 세션·상태 별도 조회와 이전 설정 조회 함수를 호출자 이전 후 삭제한다. UI는 서버 구현의 입력 타입을 import하지 않는다.
- 초대 선점과 OTP 소비 후 실패 시 기존 복구 동작을 유지한다. 프로세스 종료·부분 저장·운영 D1 다중 Worker 경쟁은 이번 리팩터링의 보장 범위 밖이다.

가정: 정책을 운영 중 편집할 요구가 없고 인증 정책값과 DB 제약은 그대로 유지한다. 접근 결정은 매 요청의 현재 설정을 사용하며 전역 권한 캐시는 만들지 않는다.
검증: `pnpm verify` 통과(35개 파일, 테스트 297개), 인증·공개 신청 E2E 4개 통과, 프로덕션 빌드 통과. 가입 모듈의 최초/초대 성공, 잘못된 코드·승인 없는 가입·가입 실패의 초대 해제, 기존 SMS·TOTP 계약을 확인했다. 신규 가입의 브라우저·D1 전체 흐름, 실제 SMS 수신, 다중 Worker 경쟁·프로세스 종료 복구는 검증하지 않았다.
