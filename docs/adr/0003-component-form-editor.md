# ADR-0003: 관리자 폼 편집기를 JSON 입력에서 컴포넌트 편집기로 교체

- 상태: 채택 (Accepted)
- 작성일: 2026-11-04
- 선행: ADR-0002 (§1 "폼 편집 UI: 1차는 JSON 편집기")

## 배경 / 문제

ADR-0002에서 1차 편집 UI를 JSON 텍스트 편집기로 두었다. 서버(`parseFormDefinition`)가 발행 전에 검증하므로 잘못된 정의가 운영에 나가지는 않았지만:

- 오류는 저장 후에야 `fields.3.options.0.value` 같은 경로로만 보였다.
- 필드 id·옵션 값이 여러 곳(페이지 배치, 조건, 식별/연락처, 선택지별 금액, 알림 변수)에서 문자열로 참조되어, 이름 하나를 바꾸면 손으로 모든 참조를 맞춰야 했다.
- 비개발자 관리자가 쓸 수 없었다.

## 목표 / 비목표

- 목표: 참조 무결성을 입력 단계에서 구조적으로 보장하고, 남는 오류는 즉시 해당 칸 옆에 보여준다.
- 비목표: 드래그앤드롭, 실행 취소(undo), 정의 스키마 변경, 서버 검증 완화.

## 렌더링 / 메모리

- 접힌 질문 카드는 요약 한 줄만 그리고 편집기를 마운트하지 않는다. 비활성 탭과 접힌 영역도 언마운트한다.
- 컨텍스트를 변경 빈도별로 분리: 액션(불변) / 인덱스(구조 변경 시) / 검증(지연).
- `FieldCard`·`OptionRow`는 `memo`. 리듀서의 구조 공유 덕분에 다른 질문을 편집해도 리렌더되지 않는다.

## 가정 (확인 필요)

- **발행된 질문의 ID는 편집기에서 잠근다.** 기존 응답(시트 헤더는 라벨 기준이지만 큐 payload·알림 변수는 id 기준)이 깨지지 않게 하기 위함. 서버는 이를 강제하지 않는다(삭제 + 새 질문과 구분할 수 없으므로). 필요하면 발행 시 서버 검사를 추가한다.
- 선택지 저장 값은 편집 가능(기본 숨김)하며 조건/금액 참조에 연쇄 반영한다. 시트에는 라벨이 기록되므로 기존 응답은 영향이 없다고 판단했다.
- 편집기가 표현할 수 없는 조건(그룹 안의 그룹)은 변경하지 않고 "조건 지우기"만 제공한다. 기존 JSON으로 만든 정의 호환을 위해서다.
- 구조가 손상된 초안(필드 타입 불명 등)은 열지 않고 빈 폼으로 다시 시작하는 선택지만 준다. 저장하기 전까지 기존 초안은 바뀌지 않는다.
