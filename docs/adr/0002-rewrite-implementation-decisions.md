## 2. void 1.5 프레임워크 모드의 큐/크론 (중요)

빌드 산출물을 확인한 결과, TanStack Start(프레임워크 모드)의 운영 빌드는

- `crons/`에서 cron 트리거는 `wrangler.json`에 넣지만 워커에 `scheduled` 핸들러를 붙이지 않고,
- `queues/`를 `wrangler.json`의 `queues`에 반영하지 않으며 `queue` 핸들러도 붙이지 않는다.

그래서 `void.config.ts`에 `cloudflare.main = "./server.ts"`와 `cloudflare.queues`를 명시하고, `server.ts`가 `scheduled`/`queue`를 `crons/`·`queues/` 모듈로 분배하도록 했다. 빌드 결과 `wrangler.json`에 생산자/소비자/크론이 모두 들어가고 워커가 두 핸들러를 내보내는 것을 확인했다.

void가 이후 버전에서 프레임워크 모드 큐를 지원하면 설정이 중복될 수 있다. 업그레이드 시 `dist/server/wrangler.json`의 `queues`를 확인할 것.

## 3. 확인하지 못한 가정 (배포 전 확인 필요)

1. **큐 프로비저닝**: `void deploy`가 `cloudflare.queues`에 명시한 큐(`jwc-form-sheets`, `jwc-form-sms`)를 자동 생성하는지 확인하지 못했다. 생성하지 않으면 한 번 `wrangler queues create`로 만든다.
2. **Solapi v4 단건 발송 API**: `POST /messages/v4/send`, `{ message: { to, from, text } }`, HMAC 인증 헤더 형식은 공식 문서 기준으로 작성했고 가짜 fetch 계약 테스트만 통과했다. 실제 키로 1건 발송 확인이 필요하다 (`SMS_MODE=live`).
3. **Google Sheets 실연동**: 서비스 계정 JWT 서명은 실제 RSA 키로 검증했지만 Google API 실호출은 하지 않았다.
4. **기존 데이터**: Convex 응답 이전은 하지 않는다(처음부터 새로 시작). 필요하면 기존 시트를 읽기 전용으로 보관한다.
5. **시트에서 답변 필드 수정 시 SMS 재발송**: 하지 않는다. 납입여부/연락처만 D1에 반영한다.
6. **동시 편집**: 큐에 아직 반영 전인 제출이 있을 때 운영자가 같은 행을 시트에서 고치면, 뒤이어 도착한 큐 메시지가 그 셀을 덮어쓸 수 있다 (짧은 창, 허용).
