# ADR-0019: Cloudflare Worker와 큐 이름 고정

- 상태: 채택
- 작성일: 2026-11-09
- 보완: ADR-0002의 프레임워크 모드 큐 설정

## Problem 1-Pager

- 배경: SMS 큐는 `jwc-form-sms`로 명시했지만 Worker 이름은 설정하지 않았다.
- 문제: Void 1.6.2의 Secret 명령은 Worker 이름 누락으로 실패한다. 배포는 패키지명 `web`을 사용해 `web-sms`를 추론하므로 기존 `QUEUE_SMS` 바인딩과 충돌한다.
- 목표: Secret 명령과 배포가 같은 Worker를 선택하고, 추론한 큐와 명시한 큐의 이름을 일치시킨다.
- 비목표: 원격 배포·Secret 등록, 기존 리소스 삭제, SMS 처리·재시도 정책 변경.
- 제약: 이미 기록된 D1 연결을 보존한다. 실제 환경 파일과 배포 자격 증명을 읽지 않는다.

## 대안

| 대안                                    | 장점                                                        | 단점·위험                                                    | 결정   |
| --------------------------------------- | ----------------------------------------------------------- | ------------------------------------------------------------ | ------ |
| `cloudflare.name`을 `jwc-form`으로 고정 | 기존 SMS 큐·소비자 이름 유지, 패키지명 변경에 영향받지 않음 | 이미 다른 이름의 Worker를 운영 중이면 별도 이전 검토 필요    | 채택   |
| Worker를 `web`, 큐를 `web-sms`로 변경   | 현재 패키지명과 자동 추론 이름 일치                         | 기존 큐의 메시지·소비자 이전이 필요하고 런타임 이름도 변경됨 | 미채택 |

## 결정과 영향

- `void.config.ts`의 `cloudflare.name`을 `jwc-form`으로 명시한다. Void가 `queues/sms.ts`에서 추론하는 큐는 `jwc-form-sms`가 되어 기존 `QUEUE_SMS` 및 런타임 소비자와 일치한다.
- 명시한 Worker 엔트리와 생산자·소비자 옵션은 유지한다. 설정과 큐 파일 경로 사이의 이름 계약을 회귀 테스트로 검증한다.
- 공개 성능 설정으로 로컬 빌드해 생성 설정과 `void.lock.json`을 갱신한다. `void prepare`는 타입만 갱신한다. 실패한 배포가 기록한 D1 이름·ID·계정 연결은 그대로 유지한다. D1 이름이 Worker 이름과 달라도 기록된 바인딩을 사용한다.
- 가정: 기존 큐 이름을 유지하며 앞으로 사용할 배포 대상 Worker는 `jwc-form`이다. 원격의 활성 Worker·소비자는 이번 로컬 수정으로 확인하거나 변경하지 않는다.
- 실패한 배포가 만든 `web-db`·`web-sms` 등의 원격 리소스는 자동 삭제하지 않는다. 운영 담당자가 사용 여부와 잔여 메시지를 확인한 뒤 정리한다.

## 검증

- 수정 전 회귀 테스트 2개가 Worker 이름 누락과 큐 이름 불일치로 실패했고, 수정 후 모두 통과했다.
- `pnpm -C apps/web with-env:performance vp build --mode performance`가 통과했다. 생성 설정과 lock에서 `jwc-form`, `QUEUE_SMS → jwc-form-sms` 및 기존 D1 `web-db` 연결 보존을 확인했다.
- `pnpm verify`가 통과했다. 포맷·린트·의존성·미사용 코드·타입 검사와 46개 파일의 테스트 327개가 성공했다.
- 빌드의 Vite CSS 소스맵 경고와 Turbo의 타입 검사 산출물 경고는 남아 있다. 둘 다 이번 Worker·큐 이름 수정 범위 밖이며 명령은 성공했다.
- 원격 Secret 등록·배포·리소스 정리는 실행하지 않았다.
