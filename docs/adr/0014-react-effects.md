# ADR-0014: React Effect를 외부 동기화에 한정

- 상태: 채택
- 작성일: 2026-11-09
- 관련 결정: ADR-0003

## Problem 1-Pager

- 배경: 웹 앱의 Effect 11개 중 편집기 1개는 React 상태를 ref에 복사하고, 1개는 새 질문의 제목 입력을 선택한다.
- 문제: 상태 복사 Effect가 실행되기 전에 저장하거나 이동하면 오래된 정의와 변경 여부를 읽을 수 있다. DOM 연결 시점의 처리를 별도 Effect로 관리한다.
- 목표: 편집 명령이 단일 상태 원본을 읽고, DOM 연결은 callback ref로 처리한다. Effect는 외부 시스템의 동기화·구독에만 사용한다.
- 비목표: 분석 이벤트의 의미 변경, 외부 SDK 교체, 공용 UI 패키지 전체 리팩터링, 서버·저장 형식 변경.
- 제약: 순수 editorReducer, 액션 컨텍스트의 안정성, 지연 검증, 저장 중 추가 편집과 저장 실패 시 이탈 경고를 유지한다. 새 의존성은 추가하지 않는다.

## 대안

- A: useReducer를 유지하고 최신 값을 읽는 콜백을 렌더마다 교체한다. 장점은 변경량이 작다는 것이다. 단점은 액션 컨텍스트가 모든 입력마다 바뀌는 것이며, 같은 이벤트에서 편집 후 저장할 때 이전 스냅샷을 읽을 위험도 남는다.
- B: 기존 Zustand의 vanilla store를 편집기 인스턴스마다 만든다(채택). 장점은 명령과 React 구독이 같은 원본을 읽고 콜백이 안정적인 것이다. 단점은 구독 경계가 하나 생기는 것이며, 전역 store로 잘못 공유할 위험은 인스턴스별 초기화·격리 테스트로 막는다.

## 결정과 영향도

- 정의와 마지막 저장 스냅샷만 store에 둔다. 변경 여부는 두 참조 비교로 계산하며 별도 상태나 ref로 복사하지 않는다.
- 기존 editorReducer는 그대로 사용한다. dispatch 직후 getDefinition과 isDirty가 최신 상태를 반환한다.
- 저장 응답은 요청한 스냅샷만 저장 완료로 표시한다. 응답 대기 중 추가한 편집은 미저장으로 남는다.
- 제목 선택은 안정적인 callback ref에서 처리한다. 입력할 때마다 선택이 반복되지 않도록 한다.
- 분석 전송·관리자 식별·오류 보고, 분석 SDK 초기화·리플레이 경로 동기화, Turnstile 수명 관리, 전역 저장 단축키 구독은 외부 동기화 Effect로 유지한다.
- 가정: initial은 편집기 마운트 때 한 번 읽고 같은 편집기에서 서버 재조회로 덮어쓰지 않는 기존 동작을 유지한다. store는 브라우저 저장소에 영속화하지 않는다.

## 검증

- 신규 테스트 8개: 동일 이벤트의 편집·저장, 저장 실패, 저장 대기 중 추가 편집, 인스턴스 격리, 저장 단축키, StrictMode에서의 제목 선택·선택 없음·재렌더 시 커서 유지.
- Node 24와 공개 더미 설정에서 `pnpm verify` 통과 (39개 파일, 테스트 307개). 포맷·린트·의존성·미사용·타입 검사 포함.
- 프로덕션 빌드와 기존 공개 신청·관리자 인증 E2E 4개 통과. 편집기 회귀 테스트는 jsdom의 실제 React 컴포넌트로 실행하며, 편집기 전체의 브라우저 E2E를 추가한 것은 아니다.
- Turbo 타입 검사 output 경고, CSS sourcemap 경고, E2E의 NO_COLOR/FORCE_COLOR 경고는 기존 상태로 남아 있다. 실제 외부 서비스 연결이나 운영 배포는 수행하지 않았다.
