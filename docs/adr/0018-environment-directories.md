# ADR-0018: 환경별 설정 폴더

- 상태: 채택
- 변경: ADR-0013의 로컬 파일 경로. dotenv와 CI codegen 결정은 유지한다.

## Problem 1-Pager

- 배경: 일반 개발은 공개 더미, 실제 개발은 루트 `.env`, E2E와 성능 검사는 파일·코드의 값을 조합했다.
- 문제: 파일 위치만 보고 환경을 구분하기 어렵고 테스트가 기본 개발 설정에 의존했다.
- 목표: `config/env/`에서 개발·테스트·성능·운영 등록 항목을 구분하고, 개발 명령은 `dev` 하나로 통일한다.
- 비목표: 실제 서비스 연동 실행, 운영 키 변경·배포, AI 격리 환경 구현.
- 제약: 일반 dotenv 사용, `dev` 이름 유지, 실제 파일 내용 보존과 비밀값 미출력·Git 제외.

## 대안

| 대안                                | 장점                                        | 단점·위험                                | 결정   |
| ----------------------------------- | ------------------------------------------- | ---------------------------------------- | ------ |
| 환경별 폴더와 명시적 dotenv 경로    | 파일과 명령의 관계가 보이고 기존 CLI 재사용 | 환경별 더미 선언 일부 중복               | 채택   |
| 한 폴더의 파일을 자동 선택하는 로더 | 파일 수가 적음                              | 선택 규칙이 숨겨지고 새 런타임 코드 필요 | 미채택 |

## 결정과 영향

- 사용자 요청에 따라 개발은 `dev` 하나로 통일하고 `with-env`가 Git에서 제외한 `development/.env`를 읽는다. 중복된 real 별칭과 사용하지 않는 개발용 더미 파일은 제거한다.
- real 별칭만 삭제하고 기본 개발을 더미로 유지하는 대안도 비교했다. 변경은 작지만 실제 설정을 사용할 개발 명령이 사라지므로 채택하지 않았다.
- 개발용 예시는 `development/.env.example`로 옮긴다. 기존 루트 실제 `.env`는 내용과 권한을 보존해 새 경로로 이동한다. 대상이 있으면 덮어쓰지 않는다.
- E2E는 `test/defaults.env`, 성능 검사는 `performance/.dev.vars`를 각각 전용 스크립트로 주입한다. Playwright의 중복 환경 덮어쓰기는 제거한다.
- 성능 preview의 추가 바인딩도 같은 파일에서 주입한 값을 사용한다. `.dev.vars`는 Cloudflare preview가 요구하는 이름을 유지한다.
- 운영은 Cloudflare Worker Secrets가 원본이다. `production/.env.example`은 등록할 항목의 예시이며 실행·배포 시 자동으로 읽지 않는다.
- 기존 보관본과 암호화 백업은 Git에서 제외한 `archive/` 아래에 모은다. 실행 스크립트에서 읽지 않는다.
- 가정: 개발자는 `.env`를 준비해 `pnpm dev`로 실행한다. AI는 `with-env:test`와 전용 E2E·성능 명령만 사용한다. 단위 테스트는 독립된 fixture를 계속 사용하며 별도 비밀 파일이 필요 없다. 테스트·성능 데이터는 실제 외부 서비스에 접근하지 않는다.
- 폴더는 설정 공급원을 구분한다. Void 생성 메타데이터는 공유되므로 dev·타입 검사·E2E·성능 검사는 순차 실행한다.

## 검증

- 기존 코드에서 전용 주입 명령 누락과 실제 개발 파일 경로 선택 오류로 회귀 테스트 3개가 실패하는 것을 확인했다.
- 실제 CLI 회귀 테스트 5개가 환경 선택·상속 값 덮어쓰기·`$`와 여러 줄 값 보존·값 미출력·루트 파일 미사용을 확인한다.
- 실제 파일 이전은 내용 일치·권한 `600`·Git 제외를 확인했으며 값을 출력하지 않았다.
- 비밀 파일을 복사하지 않은 임시 작업 공간에서 Node 24로 `pnpm verify`(단위 테스트 322개)와 E2E 11개가 통과했다.
- 성능 전용 설정으로 production preview를 빌드·실행하고 17개 화면을 1회 표본으로 검사했다. 글꼴 교체 검사 3개를 포함해 4개 테스트가 통과했다. 기본 5회 측정 설정은 유지한다.
- 개발 명령을 하나로 통일한 뒤 `pnpm verify`(단위 테스트 325개)가 통과했다. 실제 값 대신 더미 `.env`를 둔 임시 작업 공간에서 루트 `pnpm dev`의 로그인 화면 HTTP 200과 미인증 관리자 접근의 로그인 리다이렉트를 확인했다.
