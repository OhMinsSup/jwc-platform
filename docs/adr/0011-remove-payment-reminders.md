# ADR-0011: 미입금 리마인드 문자 제거

- 상태: 채택
- 작성일: 2026-11-06
- 관련 결정: ADR-0001, ADR-0003, ADR-0006의 미입금 알림 관련 결정을 대체한다.

## Problem 1-Pager

- 배경: 미입금 리마인드는 매일 크론에서 대상·이력을 읽고 SMS 큐에 넣으며 편집기에서 주기와 문구를 설정한다.
- 문제: 사용자가 미입금 리마인드 메시지 기능 제거를 요청했다. 화면만 숨기면 기존 정의와 큐를 통해 계속 발송될 수 있다.
- 목표: 예약 발송·대상 판단·규칙·문구 편집·횟수 표시를 제거하고 이미 대기 중인 리마인드도 발송하지 않는다.
- 비목표: 신청·수정 완료 문자, 관리자 SMS 인증, 납입 변경·미납자 조회, 기존 발송 기록 삭제, 운영 배포.
- 제약: 기존 폼 버전과 답변은 유지한다. 속도 제한 카운터 정리 크론을 보존하고 개인정보·인증정보를 기록하지 않는다.

## 대안

- A: UI와 크론에서만 리마인드를 끈다. 장점은 작은 변경이다. 단점은 사용하지 않는 설정·판단 코드가 남는 것이며, 위험은 대기 중인 큐가 계속 발송되는 것이다.
- B: 리마인드 전용 코드를 제거하고 SMS 소비 경계에서 현재 지원하는 종류만 허용한다(채택). 장점은 설정과 실행 경로가 함께 사라지는 것이다. 단점은 관련 타입·테스트 수정 범위가 넓은 것이며, 위험은 기존 정의 호환성과 공통 문자 발송 영향이다. 기존 정의 파싱과 큐 발송 테스트로 검증한다.

## 결정과 영향도

- `payment.reminder`와 `notifications.onReminder`를 현재 정의 스키마에서 제거한다. 기존 schemaVersion 1 정의는 Zod의 알 수 없는 키 제거로 읽으며, 해당 설정을 실행하지 않는다. 새 버전 번호·DB 마이그레이션은 필요하지 않다.
- 공개 신청·수정 알림과 납입 상태 원본은 유지한다. 관리자 목록에서는 발송 이력 집계를 없애고 안내 문자 횟수 표시도 제거한다.
- 크론은 같은 시각(매일 00:30 UTC)에 속도 제한 카운터 정리만 수행한다. 기존 예약 표현식으로 실행돼도 리마인드를 생성하지 않는다.
- SMS 큐는 메시지 구조를 검증하고 현재 지원하는 종류만 발송한다. 이미 들어간 `onReminder`와 지원하지 않는 종류는 복호화·외부 발송·발송 기록 없이 소진한다.
- 과거 `message_log`와 DB 마이그레이션은 발송 사실 보존을 위해 변경하지 않는다. DB의 과거 메시지 종류가 현재 발송 허용 목록이 되지는 않는다.

가정: 기능 제거는 다음 배포 이후 동작에 적용하며, 실행 중인 이전 Worker의 외부 SMS 전송을 취소하지는 않는다. 이번 작업에서는 실제 배포·실제 문자 발송을 하지 않는다.

## 검증

- 기존 리마인드 설정을 가진 폼이 읽히고 제거된 설정은 파싱 결과에서 사라지는지 확인한다.
- 대기 중인 리마인드가 발송되지 않고, 신청·수정 완료 문자는 계속 발송되며 중복 키는 건너뛰는지 확인한다.
- `pnpm verify` 통과: 정적 검사·타입 검사와 36개 파일의 테스트 297개. 리마인드 전용 테스트를 제거하고 정의 호환성·큐 발송 경계 테스트를 추가했다.
- 인증·공개 신청 성공/실패 E2E 4개와 프로덕션 빌드가 통과했다. 실제 Solapi 발송·운영 배포는 하지 않았다.
