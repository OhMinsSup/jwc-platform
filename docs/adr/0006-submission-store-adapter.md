# ADR-0006: 응답 저장소 어댑터(Google Sheets 주 DB), 웹훅 제거, 관측성/보안

- 상태: 채택 (Accepted)
- 작성일: 2026-11-04
- 대체: ADR-0001/0002의 "응답 인덱스(D1) + 시트 동기화 큐 + Apps Script 웹훅" 구조

## Problem 1-Pager

- **배경**: 응답 본문은 시트, 상태(납입/알림/동기화 revision/락)는 D1 `submissions`에 나뉘어 있었다. 제출은 D1에 먼저 쓰고 `sheets` 큐가 나중에 시트로 옮겼고, 운영자가 시트를 고치면 Apps Script `onEdit` 웹훅이 D1을 따라 고쳤다. 웹훅 누락은 미입금 크론이 "자가 치유"로 메웠다.
- **문제**: 같은 사실(납입 여부)이 두 곳에 있어 어긋날 수 있다. 시트를 주 DB로 쓰려면 변경 통지(웹훅)가 필요 없다. 서비스가 시트/D1 구현에 직접 묶여 저장소를 바꿀 수 없다. 로깅은 콘솔 JSON뿐이고 요청 상관관계/오류 분류/제품 지표가 없다.
- **목표**: (1) 응답 저장을 `SubmissionStore` 포트 뒤로 숨기고 Google Sheets 어댑터를 주 DB로 쓴다. (2) 웹훅·시트 동기화 큐·D1 상태 컬럼을 없앤다. (3) 판단은 순수 함수(데이터 반환), 실행은 얇은 해석기로 나눈다. (4) 요청 ID, 오류 카탈로그, 이벤트 카탈로그, PostHog. (5) 공개 제출 보호, 보안 헤더, 관리자 인증 강화, 감사 로그.
- **비목표**: 다른 DB 어댑터(D1/Postgres) 실제 구현 — 계약 테스트로 교체 가능성만 보장한다. 폼 정의 저장소(D1) 구조 변경.
- **제약**: Workers 런타임(Node SDK 일부 불가), Sheets API 할당량(서비스 계정당 분당 약 60 요청), 시트에는 유니크 제약/트랜잭션이 없다. D1은 폼/버전/인증/발송 기록용으로 유지한다.

## 단계

1. 저장소 포트/어댑터, `submission_keys`, 웹훅·시트 큐 제거, 제출 동기 쓰기
2. 순수 계획 함수 + 해석기, 오류 카탈로그, 이벤트 카탈로그
3. 관측성(요청 ID, 로그, PostHog)
4. 보안(제출 보호, 헤더/CSP, 인증 강화, 감사 로그)

## 구현 메모

- **저장소**: `src/server/store/` (포트 `submission-store.ts`, 어댑터 `google-sheets/`, `memory-store.ts`). 계약 테스트 `test/store-contract.ts`를 모든 어댑터가 통과한다. 공급자 오류는 `SubmissionStoreError`(unavailable/forbidden/layout/not_found)로 바꿔 던진다.
- **Sheets 재시도**: 읽기·덮어쓰기는 429/5xx를, 행 추가·탭 생성은 429만 짧게 재시도한다(5xx는 이미 반영됐을 수 있어 중복 행 위험).
- **판단 함수**: `src/server/domain/` (`admitSubmission`, `planSubmissionWrite`, `composeSms`, `planReminders`). 서비스는 이 결과를 실행만 한다.
- **오류 카탈로그**: `src/server/errors/catalog.ts` + `classify.ts`. 서버 함수 `Result`는 `code`를 함께 돌려준다. 큐 재시도도 카탈로그의 `retryable`을 따른다(계약 위반 페이로드는 재시도하지 않음).
- **이벤트 카탈로그**: 서버 `src/server/telemetry/events.ts`, 클라이언트 `src/lib/analytics/events.ts`. 선언한 필드만 로그/PostHog로 나간다(허용 목록 + 전화번호 형태 문자열 가림).
- **관측 범위**: `src/server/telemetry/` — 요청마다 requestId(cf-ray), 응답 헤더 `x-request-id`, 큐 메시지 `traceId`. PostHog 이벤트는 응답 뒤 `ctx.waitUntil`로 batch 전송, 실패해도 서비스에 영향 없음.
- **PostHog 클라이언트**: 동적 import(별도 청크). autocapture 끔, 익명 프로필 없음, 관리자만 user id로 identify, `/r/<id>` 주소의 id 제거, 세션 리플레이는 `session-replay` 플래그 + 공개 폼 화면에서만(모든 입력·글자 가림).
- **보안 경계**: `src/server/security/` — 서버 함수/API의 상태 변경 요청에 본문 상한(1MB), 교차 출처 거절, Better Auth 공개 가입 엔드포인트 차단, 로그인 속도 제한. 공개 제출은 폼+IP당, 신청 내역 조회는 IP당 속도 제한(IP는 HMAC으로만 저장). Turnstile은 두 키가 있을 때만 켠다. 모든 응답에 CSP/HSTS 등 보안 헤더, `/r`·`/admin`에는 `no-store`.
- **CSP 선택**: nonce + `strict-dynamic`(대안 A)은 하이드레이션/프리로드 스크립트를 브라우저에서 검증하지 못해 보류했다. `'self' 'unsafe-inline'` + 출처 목록 + eval 금지 + frame-ancestors/object-src/base-uri/form-action 제한(대안 B)으로 시작한다. 후속: 라우터 `ssr.nonce`로 전환하고 Report-Only로 먼저 확인.
- **관리자 가입**: 초대 코드(이메일에 묶인 1회용, 7일, 해시만 저장)로만 가입한다. 계정이 0개이고 `ADMIN_SIGNUP_ENABLED`일 때만 첫 관리자 부트스트랩. 실패 사유와 관계없이 같은 문장을 돌려준다(허용 목록 노출 방지). DB 훅이 "서버 함수가 승인한 가입"인지 다시 확인한다.
- **감사 기록**: `audit_log`에 관리자 작업(폼 생성/발행/상태, 납입 변경, 초대, 가입)을 대상 id와 요약만으로 남긴다.

## 배포 시 확인 (가정 포함)

1. 배포 전 `jwc-form-sheets` 큐가 비었는지 확인한다(남은 메시지는 새 코드가 소비하지 않는다). 비면 Cloudflare에서 큐를 지워도 된다.
2. 스프레드시트의 Apps Script `onEdit` 트리거를 삭제한다(웹훅 경로가 없어졌다). `SHEETS_WEBHOOK_SECRET` 비밀값도 지운다.
3. 새 비밀값(선택): `POSTHOG_KEY`, `POSTHOG_HOST`, `TURNSTILE_SITE_KEY`, `TURNSTILE_SECRET_KEY`.
4. 기존 관리자 외에 새 관리자는 관리자 화면의 "관리자" 메뉴에서 초대 코드를 만들어 전달한다.

## 가정

- 기존 D1 `submissions` 데이터는 `submission_keys`로 옮긴다(마이그레이션에서 복사). 납입 여부의 출처는 이제 시트이므로 D1의 `paid` 값은 버린다 — 웹훅이 정상 동작했다면 시트와 같다.
- 응답 읽기는 현재 발행 버전 정의로 해석한다. 발행된 질문 id는 편집기에서 바꿀 수 없으므로(ADR-0003) 헤더 매핑이 유지된다.
- 운영자가 시트에 직접 추가한 행(응답 ID 없음)은 목록에 나오지 않는다(기존과 같음).
