# ADR-0009: 관리자 SMS 가입 확인과 필수 2단계 인증

- 상태: 채택
- 작성일: 2026-11-05

## Problem 1-Pager

- 배경: Better Auth와 D1을 사용하며 관리자 이메일 허용 목록, 초대, 최초 가입 경로가 있다. 기존 SMS 발송기는 Solapi다.
- 문제: 허용된 이메일을 아는 것만으로는 관리자 본인인지 확인할 수 없다.
- 목표: 이메일·비밀번호 로그인은 유지하고 가입 확인은 SMS로 한다. 인증 앱 TOTP는 필수다. 계정이 0개면 초대 없이 첫 가입이 가능하다.
- 비목표: 일반 회원 공개 가입, 휴대전화 번호 로그인, SMS로 TOTP 대체, 통신사 본인확인(PASS), 운영 배포.
- 제약: 허용 목록과 초대 유지, D1 대화형 트랜잭션 미지원, 코드·번호·복구 코드·비밀번호 로그 금지.

## 대안

- A: Better Auth 전화번호 OTP와 TOTP 플러그인 + 기존 Solapi 발송기(채택). 만료·소비·시도 횟수를 기존 인증 엔진에 맡긴다. 공개 전화번호 API가 TOTP를 우회하지 않게 별도 경계가 필요하다.
- B: 직접 OTP 생성·저장·검증 구현. 저장 정책은 자유롭지만 재사용·동시성·비밀번호 복구의 검증 부담이 늘어난다.
- C: 로그인 2단계도 SMS 사용. 인증 앱 등록이 없어지지만 사용자 선택과 다르고 번호 탈취에 두 단계가 함께 의존한다.

## 결정과 가정

- 사용자는 가입 확인만 SMS로 바꾸고 이메일·비밀번호 로그인과 인증 앱 TOTP를 유지하는 안을 선택했다.
- `ADMIN_EMAILS`와 `ADMIN_PHONES`로 관리자 이메일과 번호를 미리 연결한다. 임의 번호의 SMS 수신만으로 허용된 이메일의 관리자가 될 수 없다.
- 전화번호는 국내 휴대전화 형식으로 정규화한다. 이메일·번호 중복 설정은 거절한다.
- 계정이 0개이고 `ADMIN_SIGNUP_ENABLED`이면 초대 없이 가입한다. DB의 최초 가입 유니크 제약으로 동시 요청 두 개가 모두 최초 계정을 만들지 못하게 한다.
- 새 계정은 SMS 확인 후 생성한다. 이메일은 로그인 식별자이며 `emailVerified`를 사실과 다르게 true로 설정하지 않는다.
- 기존 계정은 비밀번호 로그인 후 제한된 세션에서 SMS 확인을 마친다. 번호 소유 확인은 통신사 본인확인과 다르다.
- OTP는 6자리, 5분, 오입력 3회, 일회용이다. 발송은 IP와 수신 번호 기준으로 제한한다. 가입 확인과 복구의 OTP 저장 식별자는 분리된다.
- 전화번호 플러그인의 공개 API는 워커와 인증 훅에서 차단한다. 승인된 서버 호출에서만 OTP를 소비하거나 기존 계정 번호를 확인한다. SMS 확인만으로 관리자 로그인 세션을 발급하지 않는다.
- TOTP와 복구 코드는 Better Auth를 사용하며 비밀·복구 코드는 플러그인의 암호화 저장 방식을 따른다. TOTP 등록 완료 시 기존 세션을 폐기한다.
- TOTP 해제 API는 차단한다. SMS 비밀번호 재설정은 기존 세션을 폐기하지만 TOTP를 해제하지 않는다.
- Solapi 설정은 기존 것을 재사용한다. `SMS_MODE=log`에서는 인증 발송을 성공 처리하지 않는다. 인증 라이브러리의 원문 로그는 끄고 앱 경계의 구조화된 실패 기록을 사용한다.

## 영향도

모든 관리자 서버 함수는 허용된 이메일, 등록 번호의 확인 상태, TOTP 활성화를 다시 검사한다. 번호 설정이 바뀌면 기존 세션도 SMS 확인을 다시 거쳐야 한다.
D1에는 관리자 인증용 번호와 확인 여부를 추가한다. 응답 연락처 저장 정책에는 영향이 없다. 배포 전에 마이그레이션과 관리자 번호·Solapi 설정이 필요하다.

## 검증

실제 Better Auth 처리기와 가짜 SMS 발송기로 이메일·번호 연결, 코드 만료·오입력·재사용·동시 소비, 공개 API 우회, 비밀번호 복구 후 TOTP 유지를 검증한다.
SQLite 마이그레이션 테스트와 별도 D1 저장소의 Playwright 성공/실패 흐름을 실행한다. 실제 문자 수신 확인은 운영 설정 후 별도로 수행한다.

## 설정 누락 회귀 수정 (2026-11-05)

### Problem 1-Pager

- 배경: SMS 요청과 관리자 라우트가 같은 런타임 관리자 설정을 조회한다.
- 문제: 런타임에서 `ADMIN_PHONES` 또는 `ADMIN_EMAILS`가 undefined이면 문자열 분리 중 TypeError가 발생한다.
- 목표: 설정이 없는 경우 화면 조회는 계속 가능하게 하고, 관리자 권한과 SMS 발송은 허용하지 않는다.
- 비목표: 관리자 번호 추정·자동 등록, 실제 문자 발송, CSP 완화, 인증 정책 변경.
- 제약: 환경 변수 접근은 runtime.ts에 유지하고 설정값·전화번호·인증번호는 로그에 남기지 않는다.

### 대안과 영향도

- A: 런타임 경계에서 누락된 목록을 빈 문자열로 정규화한다(채택). 장점은 기존 빈 목록의 거절 동작을 재사용하고 로그인 화면을 유지하는 것이다. 단점은 실제 사용 전에 운영자가 설정을 채워야 하는 것이며, 누락이 권한 허용으로 이어지지 않는지 테스트한다.
- B: 인증 설정 조회마다 오류를 던진다. 장점은 누락된 설정을 즉시 식별하는 것이다. 단점·위험은 로그인 전 관리자 라우트와 세션 조회까지 오류 화면으로 넘어가는 것이다.

가정: 관리자 목록이 없는 환경에서는 허용된 관리자가 없고, 번호 목록이 없으면 확인할 수 있는 번호도 없다.
영향도: SMS 요청·가입·세션·관리자 라우트가 사용하는 설정 경계만 변경한다. 인증 엔진, DB, CSP는 유지한다.
회귀 테스트는 설정 누락·빈 목록에서 접근 상태 조회가 예외 없이 완료되고 SMS 발송이 거절되는지 확인한다.
