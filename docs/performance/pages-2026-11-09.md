# 전 페이지 성능 측정 — 2026-11-09

17개 화면 × 5회 = 85개 표본. 모든 화면의 실험실 p75가 성능 예산을 통과했다.

## 조건

- production SSR, Playwright 1.64.1 Chromium, Pixel 7 viewport, CPU 4배 제한, cold cache.
- 다운로드 1.6Mbps·업로드 0.75Mbps·지연 150ms를 CDP로 설정. CSS/JS만 테스트 proxy로 gzip 전송.
- 로컬 Cloudflare preview·더미 D1·메모리 응답 저장소·로그 SMS. 폰트는 고정 버전 CDN.
- 실제 제목·상태·경로·브라우저 오류·입력/클릭을 함께 검사. 샘플 수가 5인 각 지표의 nearest-rank p75.

## 변경과 검증

- 모든 화면의 라우트 이동에 레이아웃을 밀지 않는 공통 진행 표시를 추가했다. router 상태를 구독하며 Effect는 추가하지 않았다.
- 이동 표시 전 1회 기준선에서 신청 내역 → 목록 INP가 240ms였다. 변경 후 5회 모두 48ms 이하였다. 단일 기준선으로 전체 페이지의 속도 개선률을 주장하지 않는다.
- 기존 공개 폼 렌더링·날짜 입력 지연 로딩·글꼴 CSS 병합·메타데이터 개선은 유지했다. 공개 신청폼을 포함한 noindex도 유지했다.
- CI에 같은 성능 예산 검사를 추가하고 라우트 누락 감지·집계 단위 테스트, 이동 성공/실패 E2E를 추가했다.
- `pnpm verify`: 319개 테스트 / 44개 파일, 정적 검사·의존성 검사·타입 검사 통과.
- 기능 E2E: 9개 통과. 실패 경로는 의도적으로 요청을 중단하므로 브라우저 오류 로그를 출력한다.
- 성능 검사: 17개 화면 × 5회 통과.

## 해석과 원본

대표 fixture의 모바일 실험이다. 로컬 응답 시간·메모리 저장소·PostHog 미설정 환경이므로 운영 서버·Google Sheets·실제 사용자 분포를 재현하지 않는다.
Google의 실제 통과 판정은 배포 후 모바일·데스크톱 각각의 실제 사용자 p75와 28일 데이터로 확인한다. RUM 설정은 기존 PostHog 키가 있을 때 숫자만 수집한다.
